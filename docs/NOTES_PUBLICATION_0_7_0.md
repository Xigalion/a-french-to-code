# A 0.7.0 — quatre langages cibles

*Corps de la release GitHub. Il se **produit**, il ne se recopie pas :*

    node scripts/notes-release.mjs 0_7_0     # écrit dist/notes-release-v0.7.0.md

---

**A** traduit une phrase française en **une** instruction, montre un aperçu, et
n'insère rien sans confirmation. Cette version ajoute un quatrième langage
cible : **SQL**.

Le projet se décline : **C-A** vers C17, **Python-A** vers Python, **Java-A**
vers Java 21, **SQL-A** vers SQL. Une seule extension porte les quatre.

**Toujours un prototype pédagogique.** Pas un produit. Et un chiffre n'a pas
bougé depuis la première version : **personne n'a encore écrit un programme
avec A**.

## SQL va au bout d'un principe que les trois autres n'avaient qu'approché

**SQL-A ne reprend aucune des 84 intentions du catalogue C17.** C'est le
premier langage dans ce cas, et ce n'est pas un appauvrissement : un langage
de requêtes n'a ni variable, ni boucle, ni fonction, ni affichage, ni fichier,
ni mémoire, ni préprocesseur.

| | |
|---|---|
| formulations | **93**, **toutes natives** |
| refus nommés | **84**, groupés en **10 raisons**, chacune désignant la construction SQL qui enseigne la même compétence |
| informations pédagogiques passives | **17** |
| placement | **3 portées** — fichier, requête, projection — et **10 rangs de clauses** |

Mesuré sur le moteur : C17 porte **84** intentions du catalogue partagé sur
84, Java **57**, Python **33**, SQL **0**. La pente suit la distance au
langage pour lequel le catalogue a été conçu.

**Le refus qui demande le plus d'attention est celui qui ressemble le plus à
un oui :** une structure est un **type** — la forme d'une valeur — et une
table est une **relation** — un ensemble de lignes. Les rendre identiques
enseignerait la confusion exacte qui fait ensuite écrire des boucles sur une
base de données.

## Une requête se compose, clause par clause, sans rien modifier

Une requête est écrite **une clause par ligne**, le `;` seul sur la dernière,
une ligne blanche avant lui. Ajouter une clause est alors une **insertion
pure** : aucun caractère existant n'est touché.

```
Crée une requête qui lit les colonnes nom et age de la table eleves.
Ne garde que les lignes où "age > 18".
Exige aussi que "age < 60".
Ordonne les lignes par age en ordre décroissant.
```

```sql
SELECT nom
     , age
FROM eleves
WHERE age > 18
  AND age < 60
ORDER BY age DESC

;
```

Le prix est visible à chaque requête : les virgules et les `AND` s'écrivent
**en tête de ligne**, parce que c'est la seule disposition où ajouter un terme
ne modifie aucune ligne existante. Et une requête écrite **sur une seule
ligne** ne se complète pas — A refuse, et il dit pourquoi.

L'ordre des clauses est imposé : une clause de rang inférieur à celui déjà
atteint est refusée, et le message **nomme** la clause qui bloque.

## SQL-A n'exécute jamais rien

Il écrit l'instruction dans votre fichier, et c'est **vous** qui lancez le
script contre la base de votre choix. **A ne sait pas si cette base contient
dix lignes ou dix millions, ni si c'est une base de production.** Employez une
base de test.

Il n'ajoute **jamais** de `WHERE` et n'en retire jamais : une modification
sans filtre n'est reconnue que si la phrase dit « **toutes les lignes** ».
L'intention destructive doit être écrite, pas déduite.

## SQL standard prioritaire, PostgreSQL vérificateur

`FETCH FIRST n ROWS ONLY` et non `LIMIT n` ; `GENERATED BY DEFAULT AS
IDENTITY` et non `serial` ; `CAST(x AS type)` et non `x::type` ;
`START TRANSACTION` et non `BEGIN`. Chaque forme propre à PostgreSQL est
**refusée en nommant la forme standard** qui enseigne la même compétence.

Une exception assumée : **`CREATE INDEX` n'est pas dans le SQL standard** et
il est pourtant au catalogue — aucune base réelle ne s'en passe, et une
information passive le dit. Une règle qui se tait sur son exception n'est pas
une règle.

`==` et `!=` sont **refusés**, et non corrigés en `=` et `<>` : les remplacer
en silence laisserait croire que les deux syntaxes existent. Et `= NULL` est
refusé en renvoyant vers `IS NULL`, parce que le serveur l'accepterait et
qu'il ne serait **jamais vrai** — ni erreur, ni résultat.

## Ce que cette version ne change pas

**C-A, Python-A et Java-A sont strictement préservés.** Différentiel contre la
0.6.0 : **1 335 559 comparaisons, 0 régression, 0 capacité perdue**, relancé
deux fois — après l'extension du noyau d'expressions, puis après celle du
lexique.

Le noyau a reçu **une** capacité, `simpleEquality`, **fermée dans les quatre
profils publiés** : en C17, en Python et en Java, `=` affecte, et le refus y
est juste. Le jeton produit porte le texte canonique `==`, donc l'arbre ne
change pas.

## Ce que cette version ne fait pas

- **aucune vérification de symboles, de types, de bornes ni de droits**, dans
  aucun des quatre langages. Une insertion acceptée n'est pas un programme
  correct ;
- **aucune sous-requête complexe** : elles sont rendues entières, et
  l'expression de table est la réponse. A ne vérifie pas qu'une sous-requête
  `IN` ne renvoie qu'une colonne ;
- **« ou » sans accent n'est pas reconnu**, et ne le sera pas : `ou` et `où`
  sont deux mots différents, et les confondre changerait le sens ;
- **hors catalogue, délibérément** : fonctions de fenêtrage, `MERGE`,
  `WITH RECURSIVE`, déclencheurs, PL/pgSQL, procédures stockées, types tableau
  et JSON, `TRUNCATE` ;
- **les classes Python** n'y sont toujours pas, ni le `else` de boucle, ni la
  boucle à test final ;
- **aucun essai par un utilisateur**, dans aucun des quatre langages. Les
  programmes de preuve sont dictés par des scripts ;
- **aucun essai hors Windows**, un seul compilateur C, un seul interpréteur
  Python, un seul JDK, un seul serveur SQL.

Tout cela est détaillé dans `docs/LIMITES_CONNUES.md`, à lire **avant** de
conclure à un défaut. *(Chemin écrit en clair et non en lien : ce document est
un gabarit à coller dans une release, où un lien relatif se résout contre la
racine du dépôt et non contre `docs/`.)*
